## Concept

### 1. A view describes what should appear

In React Native, a component returns JSX. In SwiftUI, a type conforming to `View` describes its content through a property called `body`.

```swift
import SwiftUI

struct ReadingNote: View {
    var body: some View {
        Text("Read one chapter")
    }
}

#Preview {
    ReadingNote()
}
```

Read the syntax this way:

- `struct ReadingNote` declares a value type named `ReadingNote`. For today, think of this as the definition of a reusable UI component.
- `: View` means it conforms to SwiftUI's `View` protocol: a contract for describing UI.
- `var body: some View` is a **computed property**. Its braces compute the view content; it is not stored JSX or a function you call. `some View` means “a particular view type whose concrete name the caller doesn't need.”
- `Text("Read one chapter")` constructs a text view. This single-expression body doesn't need `return`.
- `ReadingNote()` creates a value of your view type. `#Preview { ... }` tells Xcode what to render in the canvas; it isn't another screen in the running app.

You would see one line of text. SwiftUI controls when it evaluates `body`, so keep it focused on describing UI. Your starter already has this structure, named `ContentView`, and already has a preview.

**Optional deeper reading:** [Apple's View reference](https://developer.apple.com/documentation/swiftui/view) covers the protocol; [previews](https://developer.apple.com/documentation/swiftui/previews-in-xcode) covers canvas options.

### 2. Build a hierarchy with stacks

Use a `VStack` for a column, an `HStack` for a row, and nest them to express groups. Here is a small reading-list header:

```swift
VStack(alignment: .leading, spacing: 12) {
    HStack(spacing: 10) {
        Circle()
            .fill(.orange)
            .frame(width: 40, height: 40)

        VStack(alignment: .leading, spacing: 2) {
            Text("Evening reading")
            Text("Chapter 3")
        }

        Spacer()
        Text("Open")
    }

    Text("A short session before dinner.")
}
```

The view tree is:

```text
VStack
├── HStack
│   ├── orange circle
│   ├── VStack: title, chapter
│   ├── flexible empty space
│   └── Open
└── description
```

`alignment:` and `spacing:` are named arguments; Swift uses `:` at the call site. `.leading` is shorthand for the alignment value Swift can infer from context. Leading means left in left-to-right layouts and right in right-to-left layouts.

The `{ ... }` after a stack is a **trailing closure**: a block passed as its content argument. SwiftUI's view-building syntax lets you list several child views in that block without an array or JSX wrapper.

`VStack(alignment: .leading)` aligns its children's leading edges. `HStack` defaults to vertical centering; `spacing: 10` sets the gap between its children. Values like `40` and `12` are points, similar to RN's logical layout units rather than physical pixels.

`Circle()` is a shape. `.fill(.orange)` colors its interior, and `.frame(width: 40, height: 40)` constrains this example to 40 × 40 points.

**Expected result:** the circle, two-line title group, and “Open” sit in one row; the description is beneath the whole row. With available width, `Spacer()` takes up spare horizontal space and pushes “Open” toward the trailing edge. In a `VStack`, a spacer instead expands vertically. It needs spare space to expand into; it doesn't create unlimited room.

This is the pattern you'll adapt to an avatar, name/handle, and “Follow.”

**Optional deeper reading:** [Stack layouts](https://developer.apple.com/documentation/swiftui/building-layouts-with-stack-views) and [Spacer](https://developer.apple.com/documentation/swiftui/spacer).

### 3. Modifiers wrap views, so order changes the result

A modifier such as `.padding(12)` returns a modified view. The next modifier works on that result. Follow the chain from the original view downward:

```swift
// A: orange behind the text AND its padding
Text("Read")
    .padding(12)
    .background(.orange)

// B: orange behind the text, clear space outside it
Text("Read")
    .background(.orange)
    .padding(12)
```

In A, you create a padded view and then paint behind that larger view. In B, you paint behind the text first and then add space outside the painted area. Both have padding; the colored bounds differ. You do not need to discover this by swapping modifiers yourself.

Now combine inner space, a background, rounded corners, and outer space:

```swift
Text("Tonight's reading")
    .frame(maxWidth: .infinity, alignment: .leading)
    .padding(12)
    .background(Color(.secondarySystemBackground))
    .clipShape(.rect(cornerRadius: 12))
    .padding(24)
```

- `.frame(maxWidth: .infinity, alignment: .leading)` adds a flexible frame that can use the width offered by the parent and places the text at its leading edge. It doesn't mean infinitely many pixels.
- The first `.padding(12)` is inside the later background.
- `Color(.secondarySystemBackground)` turns an iOS system background color into a SwiftUI color. It adapts to light/dark appearance.
- `.clipShape(.rect(cornerRadius: 12))` clips the result so the background has rounded corners.
- The last `.padding(24)` creates clear space outside the colored card.

**Expected result:** a wide, rounded background with 12 points inside and 24 points outside. A parent proposes space, and children respond to that proposal; text usually takes its content size unless layout wrappers give it more room.

To place the entire card at the top of the available screen area, append this modifier **after the card's outer padding**:

```swift
.frame(maxHeight: .infinity, alignment: .top)
```

This is a chain fragment, not a standalone expression. It creates an available-height frame and positions the card at its top. Putting the card background after this frame would paint behind that taller frame too. Stack alignment positions children within a stack; frame alignment positions a view inside its frame.

**Optional deeper reading:** [Configuring views](https://developer.apple.com/documentation/swiftui/configuring-views) explains modifier composition.

### 4. Layer a decoration with overlay

An overlay puts new content in front of an existing view. Use it when the base view should determine the layout size—for example, a status mark attached to an icon.

```swift
Circle()
    .fill(.orange)
    .frame(width: 48, height: 48)
    .overlay(alignment: .topTrailing) {
        Circle()
            .fill(.purple)
            .frame(width: 12, height: 12)
            .overlay {
                Circle().stroke(.white, lineWidth: 2)
            }
    }
```

The first circle is the base. The outer overlay places the 12-point purple circle at the top-trailing corner of the base's **48 × 48 rectangular bounds**. In a left-to-right layout, that's top-right.

The inner overlay draws a white outline on the small circle. `.stroke` draws the shape's outline rather than filling it; `lineWidth: 2` gives a 2-point stroke centered on its edge, so 1 point extends outside. With no alignment argument, this inner overlay is centered.

**Expected result:** an orange disk with a small, white-ringed purple mark at its top-right corner. The decoration doesn't make the base reserve extra layout space. Attach the overlay after the avatar's size modifier, rather than to the whole card, so it uses the avatar's bounds.

For peer views that should share a layered container, use `ZStack`:

```swift
ZStack(alignment: .bottomTrailing) {
    Circle()
        .fill(.orange)
        .frame(width: 48, height: 48)
    Circle()
        .fill(.purple)
        .frame(width: 12, height: 12)
}
```

Later children draw in front. Unlike an overlay, the `ZStack` takes its children's sizes and alignment into account when determining its own size; there is no designated base view. It has an `alignment` argument, but **no `spacing` argument** because it layers rather than arranges a row or column.

**Optional deeper reading:** [Overlay](https://developer.apple.com/documentation/swiftui/view/overlay(alignment:content:)) and [ZStack](https://developer.apple.com/documentation/swiftui/zstack).

### 5. Add text hierarchy and a pill shape

Text modifiers can communicate which information matters most:

```swift
VStack(alignment: .leading, spacing: 4) {
    Text("Evening reading")
        .font(.headline)
    Text("Chapter 3 · 15 minutes")
        .font(.subheadline)
        .foregroundStyle(.secondary)
    Text("A longer description of the chapter and what to look for as you read.")
        .font(.body)
        .lineLimit(2)
}
```

`.headline`, `.subheadline`, and `.body` are semantic font styles that participate in Dynamic Type, the user's text-size preference. `.foregroundStyle(.secondary)` gives text a secondary visual emphasis rather than hard-coding a gray color. `.lineLimit(2)` allows **at most** two lines; it doesn't force short text to occupy two. Longer text truncates when it cannot fit within that limit and the available width.

For a label with a pill-shaped background:

```swift
Text("Open")
    .font(.subheadline.weight(.semibold))
    .padding(.horizontal, 12)
    .padding(.vertical, 6)
    .background(.orange, in: .capsule)
    .foregroundStyle(.white)
```

`.weight(.semibold)` adjusts the font's weight. Axis-specific padding adds room on the left/right or top/bottom. `.background(..., in: .capsule)` paints a rounded pill behind the already-padded label. `.foregroundStyle(.white)` colors its text.

**Expected result:** a semibold white “Open” label inside an orange pill. This is still `Text`, **not a working button**. The exercise's “Follow” label is also purely visual; no action or state is required today.

**Optional deeper reading:** [Text](https://developer.apple.com/documentation/swiftui/text) covers fonts, appearance, and truncation.

### Coming from React Native

| React Native | SwiftUI | Watch out |
|---|---|---|
| Component returning JSX | `struct ...: View` with `body` | `body` is a computed property. |
| Column/row `View` containers | `VStack` / `HStack` | Choose the container for the direction; this isn't flexbox. |
| `gap` and `alignItems` | `spacing` and stack `alignment` | A stack's alignment acts across its main axis. |
| Flexible empty `View` | `Spacer()` | Expands along the enclosing stack's axis when space is available. |
| Padding/background styles | Chained modifiers | Each modifier acts on the preceding result; order matters. |
| Absolutely positioned badge | `.overlay(alignment:)` | The base dominates layout size. |
| `numberOfLines={2}` | `.lineLimit(2)` | A maximum, not a fixed height. |
| Storybook story | `#Preview` | Editor preview, not app navigation. |
